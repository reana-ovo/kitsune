# 首次配置实验

目标是让用户亲自经历安装、访谈、生成个人文件和首次日常接入，而不是把维护者的既有配置换个名字。安装成功、配置完成和新会话加载成功需要分别记录。

## 先确定干净起点

从零是指没有旧 kitsune 入口、个人配置或旧个人要求参与这次实验，不是卸载宿主或删除所有账号数据。

在用户明确授权的范围内核对：

- 当前宿主的技能目录或目录链接中，是否已有 kitsune 的两个入口，是否存在旧 automate-me 或旧 mode 副本。
- 个人启动文件是否还要求使用旧 mode、playbook 或已有个人偏好。没有标记不代表没有旧内容。
- 是否存在个人目录、安装旁的 `local/workflow.json` 或 `local/integrations.json`。没有才是首次配置；有就先备份并明确处理，不假装不存在。
- 用户规则目录、项目指令、自动记忆、插件或 hooks 是否会带入旧个人要求。来源说明见[接入文档](integration.md#宿主还会读取什么)。

需要撤下旧配置时，先展示精确路径和影响范围，获得授权后备份、校验再移除。保留无关用户内容，不通过改权限绕过限制。删除发现链接不能递归删除它指向的独立技能。备份不要留在技能扫描目录，也不要把它作为实验输入。

保留登录凭据、模型与权限配置、组织策略、无关插件以及其他项目记忆。已存在但未自动加载的独立能力不自动成为用户选择的工作方式。若它们确实影响本轮实验，记录影响并另行处理，不宣称环境完全没有宿主默认行为。

## 在新目录、新会话里安装

使用仓库外、没有旧项目记忆的空目录。检查其上层指令，不在 kitsune 开发目录内做首次用户实验，也不恢复或分叉已有讨论。旧项目记忆无需删除，只要不把它带入实验。

将仓库作为安装源，不把它变成实验工作目录。把下面的路径占位符换成本地实际路径，再发送一句话：

```text
请读取 <kitsune 仓库的绝对路径>/INSTALL.md，为当前 agent 安装 kitsune-mode 和 kitsune-setup；保持当前工作目录，不读取旧会话、个人记忆或备份来推断我的偏好。
```

需要集中安装时，在这句话后指定安装目录。例如可以要求放在 `~/.cc-switch/skills/`，但这不是所有新用户的必选项。

预期结果是两个完整技能及必要的发现链接。安装不应生成个人目录，不改全局启动文件，也不开始偏好访谈。确认宿主实际发现入口；手动技能不出现在自动调用列表中不等于安装失败。

宿主可能在读取安装源时加载该目录的项目指令。它们只约束相关项目操作，不能变成被访谈用户的个人偏好。若仍出现旧个人要求，先找出其加载来源再继续。遇到同步工具重新创建旧链接，也要记录并处理，不能靠忽略它们宣布清理成功。

## 用户主动开始配置

用当前工具支持的方式调用 `kitsune-setup`。在 Claude Code 中输入：

```text
/kitsune-setup
```

入口应先询问参考目录及读取边界。用户可以提供代表性项目，也可以选择只用任务描述和片段。不要用本仓库虚构样例替代用户回答，也不从这次安装指令推断长期工作偏好。

记录它是否做到：

- 先预读用户获准的材料，再提出日常场景。
- 对未决取舍给出具体问题和推荐，不让用户给所有规则排名。
- 区分个人要求、项目规则、单次限制和未确认推断。
- 询问遗漏场景，展示个人文件和可选技能的草案。
- 在明确范围内保存用户确认的结果，不提前安装可选技能或更改全局启动文件。

没有显式路径或既有绑定时，个人目录应为实际用户的 `~/.kitsune/workflow/`。生成完成前它不应被填入虚构偏好。

## 日常入口完成首次接入

个人文件准备好后，主动激活 `kitsune-mode` 或在日常请求中观察它是否被选择。检查它是否读取真实个人核心，并核对当前宿主的加载能力。

如果它建议修改个人启动文件，应说明具体目标、原生导入或内嵌方式，以及将写入的内容。只在取得相应授权后应用。当前工具的接入不等于授权修改其他工具。

用户拒绝时保留 skill 激活方式，不要求为完成测试而接受。没有启动机制时也应明确说明，不把一句“请读取个人目录”描述为宿主已经注入内容。

## 再开会话核验

在已经完成接入的同一宿主上开启另一个新会话，提出普通任务，不先手动加载 kitsune。通过宿主实际加载信息或可观察的文件读取检查核心是否进入上下文。仅让 agent 说“我已读取”不算证据。

分别记录：

| 项目 | 应记录的证据 |
|---|---|
| 安装 | 源与目标、文件比较、发现链接、宿主是否识别入口 |
| 访谈 | 实际问题、用户回答、覆盖与遗漏、需修正的推断 |
| 生成 | 实际个人目录、已确认要求、所选技能、未决事项 |
| 接入 | 获准目标、实际差异、导入或内嵌方式、接入记录 |
| 新会话加载 | 宿主诊断或实际读取的文件，而非上轮写入成功 |
| 行为 | 新任务中是否遵守范围、例外、语言和维护边界 |

加载正确不代表行为必然正确。没有执行的项目标为未验证，不从一次试用推断其他宿主都可用。自动化模型实验或额外会话需要另行确定预算和副作用；本指南不授权 agent 自行运行它们。
