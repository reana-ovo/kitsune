# 检查与验证

## 本地检查

```bash
node tests/check-workflow.mjs
```

```bash
node tests/check-maintenance.mjs
```

使用 Node.js 22 或更新版本，无需安装依赖。两项检查均不读取真实个人配置或安装副本，不访问网络，不调用模型。测试使用独立临时目录，结束后清理。

`archive/` 是不纳入 Git 的可选本地历史资料。目录不存在时，只跳过归档专属校验并明确报告，其余检查继续执行。存在但不完整或校验值错误时会失败，不按“可选”忽略损坏。

### 结构与启动预览

`check-workflow.mjs` 检查：

- 中英文首页、安装入口及 Markdown 文件和锚点链接。
- 两个完整技能的元数据、支持文件和 manual-only 标记。
- 访谈框架的六个维度、方法走查、质量对照及生成步骤的引用。
- 模板字段、虚构样例、共用 maintenance/authoring 文件和默认运行配置的一致性。
- 自主维护、诊断、原因支持的修改、检查、恢复和保留章节。
- 绑定的缺失、格式错误、版本及绝对路径约束。
- 启动预览的原生导入、内嵌内容、原文件保护、幂等、移除和错误标记处理。
- 行为案例的定义、唯一 ID 与分组。
- 存在本地归档时的链接、清单及 SHA-256。

文字和结构检查只用于发现缺项，不证明语义或模型执行正确。

### 维护工具与合成 hooks

`check-maintenance.mjs` 在临时 profile 中调用实际 runtime 和 adapter，覆盖：

- 缺失或停用配置无自动写入，初始化幂等且不覆盖已有不同配置。
- 多问题共享发生记录和原因，一个问题保留多个候选原因，引用校验及事件重放去重。
- 查询和相同内容不刷新时间，问题时间不因时钟回退而变旧。
- 归并、连续归并、撤销和拆分，以及后续分类变化保护。
- 版本前提、应用幂等、失败检查不可改写成通过、一轮一批修复，以及清理后仍保留本轮预算凭证。
- 同文件独立后续编辑、多段修改、依赖顺序、创建/删除冲突和不覆盖手工重写的回滚。
- 容量、年龄边界、零值、取消年龄条件、允许超额、共享引用闭包及删除历史不撤销生效内容。
- 越界路径、链接、保留名称、损坏记录、未知工作区文件、UTF-8、BOM、CRLF 和文件大小限制。
- 活跃写锁、失效进程锁、多文件写入故障、真实子进程中途退出、恢复冲突和临时文件清理。
- 合成 SessionStart、UserPromptSubmit、PostToolUse、PostToolUseFailure 和 Stop；跳过 plan mode、子代理、中断及未知写权限，Stop 不在等待后台任务时续行。
- 一次续行限制、过期 acknowledgement 拒绝、配置停用、无 user-facing message 字段、不保存原始 prompt/tool/error payload。
- CLI 的 JSON stdin 输入和实际记录副作用。

测试执行了本地文件行为，但没有运行独立模型。合成 payload 直接调用 adapter，不证明真实宿主曾触发它。进程中断恢复不等于磁盘或断电条件下的数据库级持久性保证。

## 模型行为检查

[场景集](../tests/behavior-cases.json)保留安装、setup、日常使用、integration 和 maintenance 分组。新增定义涉及普通任务无需改规则、既有目标内安静修复、多对多原因、复发重新诊断、容量与年龄清理、停用边界、同伴消息不等于授权、Stop 限制及触发证据的区分。

执行前另行确定宿主、模型、材料、预算、允许读写的样例目录和外部副作用。没有这些授权，不启动新会话或付费实验。每个案例记录实际输入、加载内容、回复、工具动作、产物、用户干预与成本；运行示例与保留的检查案例分开。不能只让 agent 复述规则。

分别判断是否应触发、是否实际触发、文件是否进入上下文、授权边界是否保持，以及结果是否正确。单一宿主或单一案例通过不代表其他宿主、原因归类或长期效果通过。

## 本轮结果

2026-11-10，在 Windows、Node.js v24.13.0 下：

- `check-workflow.mjs` 通过 470 项静态与本地样例检查；不含 `archive/` 的独立源码副本通过 392 项，明确跳过归档专属检查。
- `check-maintenance.mjs` 在工作目录和独立副本均通过 148 项检查。
- 三个新 runtime/adapter 脚本的 `node --check` 与 `git diff --check` 通过。
- 57 个行为案例只校验了定义，没有运行模型评测。原因判断、修复选择及长期改善仍未验证。

第一轮维护测试发现，共享发生/原因记录在较早时间更新时，会把新问题的更新时间向后移动，导致清理选错目标。现已保持问题时间单调不减，相关清理测试通过。测试和代码检查还覆盖了 BOM 保留、连续归并、清理后预算保护、未知权限下不写诊断，以及进程中断的临时文件恢复。

本机安装和启用不是这些可移植测试的一部分。首次迁移写入被 Auto 拦截后，用户明确再次授权。随后两个安装副本、个人维护配置与相关文档、已有原生导入启动入口完成迁移，并保留私有恢复副本。用户级 hooks 写入和最后的私有验证记录写入再次被拦截时，先停止这些写入，没有更换工具绕过。

用户随后选择临时逐次确认，剩余写入在该选择下完成，之后恢复 Auto。最终 222 项本机核对通过，包含 24 个包文件、49 个个人链接、原绑定与方法/例子保留、启动预览无差异，以及 settings 除新增 hooks 外的值不变。没有新增长期权限规则、改模型设置、修改其他宿主或运行独立模型会话。

五个 command-hook 事件均已配置。在当前会话的真实工具调用后观察到 `PostToolUse` 凭证；一次预期的无副作用退出码 1 检查触发了真实 `PostToolUseFailure`，并收到了内部上下文及失败凭证。该失败是接入检查，不是新增的工作流缺陷，对应复核已结束。随后一条正常用户消息触发了 `UserPromptSubmit`，实际送入了本轮复核标识和内部入口。没有用直接调用 adapter 的结果冒充宿主触发。

`SessionStart` 和 `Stop` 已通过合成输入检查，但本次尚未实测其宿主事件；全新会话加载、语义归因和长期效果仍未验证。不能把事件触发或文件检查通过说成模型行为已经可靠。
