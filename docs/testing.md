# 检查与验证

## 本地检查

```bash
node tests/check-workflow.mjs
```

只需要 Node，无需安装依赖。检查不读取用户的个人配置和安装副本，不访问网络，不调用模型。临时文件仅用于本次测试，结束后清理。

`archive/` 是不纳入 Git 的可选本地历史资料。目录不存在时，只跳过归档专属校验并明确报告，其余源码和样例检查正常执行。目录存在时仍检查链接、清单和校验值；缺文件或校验值错误会失败，不按“可选”静默忽略损坏。

检查内容包括：

- 中英文首页的互相链接、安装入口和文档链接。
- 一句话安装入口、完整步骤及本地数据保留说明的基本结构。
- 两个技能的元数据、支持文件、手动配置入口的标记。
- 配置入口对覆盖框架的加载、六个访谈维度、方法走查与质量对照的引用、方法模板的质量字段及样例方法章节。
- Markdown 相对链接、模板字段、样例的个人核心及共用维护文件。
- 维护指南中的诊断、修改选择、前后检查和回滚章节，以及编写指南对它们的引用。
- 存在本地 `archive/` 时，检查旧版归档的 SHA-256 与清单基本完整性。
- 绑定数据的缺失、格式错误、版本和绝对路径检查。
- 启动预览的原生导入、内嵌内容、原文件保护、无副作用、重复运行、移除和错误标记处理。
- 测试场景的结构与覆盖分类。

场景定义存在并不意味着模型已通过它们。部分文字约定的静态检查只用于发现遗漏，不证明语义正确。

## 尚未执行的行为检查

[场景集](../tests/behavior-cases.json)覆盖目录预读、无目录起步、补查遗漏、项目范围、当前纠正与永久更新、缺失技能、缺失绑定、停用、启动证据和语言。

执行前确定宿主、模型、输入材料、预算、允许读写的样例目录，以及哪些外部动作不会发生。没有这些授权，不自动启动新会话或付费实验。

每个场景记录实际输入、加载文件、回复、工具动作、最终产物、用户干预和成本。运行时案例与未进入提示的检查案例分开。不能只让 agent 复述规则。

分别判断：

1. 是否应触发，是否实际触发。
2. 文件是否真的进入上下文，启动方式是否与声明一致。
3. 行为是否符合适用范围及授权。
4. 结果是否正确，必要验证是否完成。

同一个宿主通过也不代表其他工具已通过。需要对英语、用户语言及混合内容做比较时，使用相同任务和条件，不能预先宣布全英语更准确。

已有维护场景覆盖加载问题、方法发现、保留条件的合并、淘汰过时内容、按需拆分、低频授权边界、退步后的局部回滚、未经行为验证的明确修改，以及不自动逐任务学习。规则关系与安装场景继续保留。尚未实际比较新旧访谈的覆盖程度、方法质量或交互体验，也未验证长期优化效果。

静态检查将 `INSTALL.md` 纳入文档链接检查，并核对安装流程的基本章节、两个源入口和本地数据保留说明。它不证明 agent 会正确选择宿主目录或遵守安装边界。访谈检查确认框架引用、维度、质量字段和样例内容存在，不判断问题是否问得深入，也不证明生成方法符合用户要求。维护检查确认共用指南与样例一致、必要章节和引用存在，不执行原因诊断、候选选择或效果评估。核心模板和样例的冲突说明也有结构检查，但没有实现或验证自然语言冲突推理。

默认目录与路径优先级已加入检查范围。归档重建前已完成全部 36 个文件的解压比对；保留该本地归档时，检查脚本继续验证其校验值。新检出不需要归档。

仓库重建时核对过本机旧安装和全局启动文件未变。之后用户另行授权了本机安装及从零实验清理；各次操作记录保存在本地，不作为可移植测试脚本的依赖。文件副本、链接和当前会话技能发现的核对，不等于首次配置或新会话接入已经通过。

实际首次配置按 `first-run.md` 分项记录。本检查脚本不执行模型行为评测、首次触发率测量或真实宿主的个人核心启动加载测试，上述静态结果不能替代这些验证。
