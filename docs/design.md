# 当前设计

2026-11-07，用户确认以个人工作方式为目标重建 kitsune。该文档记录本轮采用的方案，后续直接修改，不使用 RFC/ADR 审批流程。

## 产品边界

Kitsune 提供两个技能入口、个人目录模板和本地维护工具，复用宿主 agent 的上下文、文件能力和权限。不自建模型运行程序，不默认组建专家团队。维护工具负责数据与文件操作，语义诊断和修复选择仍由当前 agent 完成。

个人工作流描述用户怎样表达、取舍和检查工作。业务项目的规范仍由项目管理，不提取成跨项目偏好。用户资料和机器路径留在本地，不成为可复用技能的默认内容。

## 配置流程

1. 简短确认希望覆盖的工作范围，接受零个、一个或多个项目、交付物、片段或任务描述。逐来源确定用途、读取范围与排除项，目录外会话单独授权。
2. 先跨获准来源有限预读，再用独立框架检查目标与产物、执行方法、质量标准、验证证据、取舍与例外、协作方式。项目提供证据，不决定整个访谈范围。
3. 将重要场景细化为有输入、产物和约束的具体任务，按问题依赖深入。agent 查证事实、提出方法草稿和可信对照，用户决定尚未委托的关键判断，不逐项确认普通实现细节。
4. 跟踪各维度的已明确、已委托、不适用、暂缓和未决状态。重要的方法或质量缺口仍存在时，不因为决策问题问完就标记完全覆盖。
5. 允许中途追加来源，只复核受影响的证据和结论。比较各项目的目标与环境，不按第一个项目或出现频率决定个人规则。结束时补查遗漏任务、资料和方法深度。
6. 区分明确要求、待确认推断、单次限制和项目规则。根据需求推荐少量技能，也允许不选择任何技能。
7. 展示行为、重要方法、质量判据、例子和文件操作范围；一并说明个人维护授权、`maintenance.json`、私有记录和有界清理，确认后保存。已有明确授权不重复确认，后续范围内维护不逐次提案；未经委托的新价值取舍仍由用户决定。
8. 检查产物及绑定状态。真实模型评测、安装、启动接入和 hooks 启用需对应授权；生成配置不顺带修改宿主设置。

[访谈框架](../skills/kitsune-setup/references/framework.md)规定要了解的维度，不规定所有用户必须采用相同工作流程。场景和维度都不是一对一的 playbook、文件或 skill 列表。简单事项按需要缩短，专业问题随实际任务补充。宿主提供选择界面时，有限选项使用该界面并保留自定义回答和暂缓；开放讨论或不支持界面时使用文字。

## 个人目录

必需内容是入口 `README.md`、`preferences.md`、`skills.md`、`maintenance.md`、`authoring.md` 和运行配置 `maintenance.json`。没有选中技能时清单明确写无，不伪造技能能力。`.maintenance/` 在运行时保存私有问题工作区及关联记录，不把整份会话或原始工具输入复制进去。

按需增加方法、例子和配置来源证据。未确认的个人价值推断只放在证据或草稿，不作为启动指令。既有目标内基于失败推导的修复方法，通过维护检查后可以自主采用，不伪称为用户亲口提出的偏好。首次生成和后续维护共用随个人目录保存的编写指南，不依赖安装源码永远存在。

启动核心仍是 `README.md`、`preferences.md` 和 `skills.md`，详细方法按任务读取；`maintenance.json`、维护明细和问题记录不进入启动核心。重要方法应保留输入和结果、执行步骤中的判断与调整、独立的质量判据，以及如何验证和何时停止。确认过的方法与质量信息不能在生成时退化成只有触发条件的偏好条款。多个任务可以共用方法，简单要求不强制生成方法文件；此次维护迁移保留已有有效方法。

少量例子解释有歧义的判断，也可用可信成果对照说明两种可行做法的质量差异，不给每条要求机械添加例子。留一部分新案例做检查，不能只测试提示里已有的答案。访谈框架、来源清单和未决覆盖项不进入日常核心。

## 语言

入口 skill、共用步骤、维护说明和代码注释用英语。个人偏好、场景和表达示例优先使用用户能准确审阅的语言。保留具体术语、原话与命令。用户选择英语个人规则时，仍检查翻译是否改变范围或语气。

回复语言单独记录。英文指令不意味着默认英文回复。同一要求只有一份生效版本，不同步维护可能分歧的中英文全文。

## 日常加载与首次接入

个人目录按固定顺序定位：本次明确指定的路径、安装目录旁的已有绑定、默认 `~/.kitsune/workflow/`。配置入口和日常入口使用同一顺序。`~` 按实际宿主用户的主目录解析，不包含固定用户名。

绑定无效或已选路径不可用时报告问题，不静默换目录。默认位置尚不存在时，只有在获准的配置流程中才创建，不在日常任务中扫描主目录或生成另一份配置。

首次激活时检查宿主。支持原生导入就优先导入；只有自动加载指令文件的能力时，可以生成受管理的核心内容；都不支持或用户拒绝时，保留 skill 激活方式。不同工具的接入不同，个人内容共用。

自动加载保证的是文件内容进入上下文，不是模型必然遵守。只写“请读取另一文件”仍然依赖模型主动读取。已经接入或已拒绝的宿主不在每次任务重复改写或询问。

个人核心保留修改判断和维护入口，因为完成接入后可能不再调用日常 skill。新增工具和同步到新位置不等于已获授权。

## 规则的范围与局部关系

访谈只检查同一场景、动作或输出维度上有关联的要求，以及历史中出现过的取舍，不让用户给全部规则排名。能同时满足的要求共同生效；适用范围不同的要求先分清条件。

生成时优先把默认和条件例外写在一起。必须分开表达时，用稳定标识或链接记录已确认的局部关系，说明触发条件、让步部分和仍然有效的要求。不按编号、文件顺序、措辞强度、读取先后或更具体的文字自动决定效力。

个人核心包含冲突处理顺序，因此原生启动加载和受管理的内嵌内容都会带上它。已知关系按条件处理；重要未决冲突只询问具体选择，其他独立工作继续。常规、可逆且已授权的判断使用既有默认，不自动生成永久优先关系。

个人规则关系不能扩大权限。本次任务的临时选择不会自动改变长期偏好。维护时检查关系引用、例子、选定技能及潜在循环，不跨不同条件盲目推导传递关系。

相关依据见[优先关系研究](research/2026-11-07-rule-precedence.md)。当前实现是说明与模板，没有规则引擎，也尚未运行对应的模型行为测试。

## 自主维护与授权

首次配置明确建立个人目标、维护写入范围、运行配置、恢复和清理授权；宿主启用另行覆盖启动文件与 hooks 的具体操作。安装包本身不授予这些权限。完成配置并启用后，正常工作中的失败、纠正、矛盾与验证结果都可触发内部复核，不只接受显式的“记住”请求，也不要求每次展示维护提案或汇报操作。

当前任务的纠正不会自动成为通用偏好，但可以提供未达到既有目标的证据。agent 可据此推导和检查修复方法，不得凭空决定用户的新价值取舍。明确限制不持久化时照做。实际任务的新目标、尚未委托的重要取舍、额外权限或外部副作用仍需询问并等待，独立的已授权工作可以继续。

每次持久修改先读个人 `maintenance.md` 和 `authoring.md`。自动尝试可以按需要修改个人偏好、方法、例子、索引和编写指南，但不能修改执行策略 `maintenance.md`、运行配置 `maintenance.json`、预算、hooks、权限、安装或业务项目文件。这次迁移若改变旧授权边界，必须明确纳入迁移授权；后续不能借自动维护自行扩大权限。这是参与者规则与工具约束的组合，不替代宿主权限控制。

## 分阶段诊断与修复

先检查实际产物和任务结果，区分失败、未完成、中断与宿主限制，再检查加载、方法发现、执行、表达、规则冲突、偏好变化或能力缺口。问题现象不等于原因；程序保存了记录也不证明归因正确。只查当前问题相关的获准资料和已有记录，不默认扫描所有旧会话。

可选处理是修正执行、不改指导、澄清、合并、替换或停用、移到按需内容，以及针对既有目标补充确实缺少的方法。保留原有具体判断，避免整份重写或累加同义禁令。没有固定规则数量目标，低频授权边界不能因使用次数少被删除。

每次内部复核最多进行一组有证据依据的自动修复。修改前记录预期改善、必须保留的行为、相关版本和检查：原问题、可能受影响的正确案例、例外及近似反例，必要时另留未写入运行示例的新案例。先检查内容与产物，再判断原因解释是否得到支持。没有新证据时停止重复失败策略；复发要重新诊断，不能机械回滚最近一次修改。

真实模型对照须有费用和副作用授权，条件应可比。静态检查、模型自评和修好单个案例都不能证明长期改善；未做行为检查时保留未验证状态，不为普通范围内修复强制开启付费评测，也不用平均分掩盖边界退步。

## 本地维护数据与恢复

[通用维护工具](../skills/kitsune-mode/scripts/maintenance.mjs)使用 Node，不依赖第三方包。它复用现有个人目录绑定、核心摘要与启动预览能力，负责持久化、引用校验、版本前提、改动应用、恢复和清理。操作契约见[运行指南](../skills/kitsune-mode/references/maintenance.md)，语义分类和修复选择由当前 agent 完成。

`.maintenance/` 内的问题、发生记录、原因假设、修复尝试和检查结果使用稳定 ID 多对多关联。多个问题可以共享原因或修改，一次发生也可以关联多个问题；共享修改只保存一份，合并与拆分保留可撤销依据。只存必要的脱敏摘要、来源位置和生效版本，不存整份会话、凭据或无关信息。配置来源 `evidence.md` 不变成无限增长的运行日志。

应用前校验当前内容和摘要，拒绝过期前提、路径逃逸和越界链接。尝试保存修改前后内容或精确补丁、目标问题和原因、先前依赖及检查结果。多文件变更有待完成和可恢复状态，不能把部分写入算成功；同一请求重放不能重复应用。

回滚针对被证据指向的修改，检查当前内容、后续依赖和用户最新目标，保留同文件内独立的后续编辑。冲突时重新评估，不整份覆盖，不恢复用户已废止的偏好。受管理的启动副本只在已有适用授权内同步；原生导入无需重复保存核心。无法同步时保留失效状态，影响实际任务或需要决定时说明。

## 有界保留

`maintenance.json` 的初始默认是 `maxIssues: 100`、`minIdleDays: 30`，后者设为 `null` 可停用时间条件。这些是产品默认值，不是研究结论，也不是自动修复可以自行调整的预算。

仅超过数量上限时，按最后有意义的 `updatedAt` 从旧到新清理；启用时间条件时，只删除足龄记录。不足以回到上限就允许暂时超额，不增加“已解决”“休眠”或“没有复发”的前置条件。查询和读取不刷新时间，新增发生、原因变化、修复和检查结果才刷新。

删除问题不会撤销已生效的工作流修改。清理专属记录与失去全部引用的共享数据，仍被其他问题引用的内容保留；移除引用不能人为刷新那些问题的时间。会话辅助状态也需过期回收，不把删除内容转移到无界冷库。

## Claude 自动触发

[Claude command-hook 适配器](../skills/kitsune-mode/scripts/claude-maintenance.mjs)与通用工具分离。`SessionStart`、`UserPromptSubmit` 提供简短内部入口与当前轮次状态；`PostToolUseFailure` 提供失败信号；`PostToolUse` 保留最小触发凭证并支持验证接入，不反复注入完整维护说明。

未处理完的轮次由 `Stop` 最多补发一次内部复核提醒，结合 `stop_hook_active` 和本地去重避免循环。中断、plan mode、子代理或等待后台工作时不强行继续或写入；同伴消息不等于用户授权。没有问题时结束复核，不制造规则。

hooks 唤起的是当前会话的 agent 内部复核，不启动另一模型、后台 agent、定时扫描器或守护进程。正常维护不输出提案、诊断卡片或报告，也不用 `systemMessage` 制造通知。宿主仍可保留工具和审计轨迹及安全提示；不能通过改显示、通知或权限来伪造不可见。其他宿主可以使用通用工具，不因此宣称已支持其自动事件。

## 验证边界

文件与 runtime 检查、合成 hook payload、实际宿主事件、全新会话加载、语义归因和实际工作行为分别验证。程序测试通过不能标记模型行为通过；只实际观察到的事件才记录为已触发，未执行的新会话或付费评测仍为未验证。具体检查入口见[检查说明](testing.md)。

可复用源码不代表本机已安装或启用。本机安装、个人迁移、hooks 接入和清理需要对应授权并单独核对。旧实现及讨论原文保存在维护者本地的 `archive/`，不纳入 Git，不作为新检出的必需文件。
