# 使用指南

## 安装入口

把这句话交给能读取本仓库的 agent：

```text
请读取这个仓库的 INSTALL.md，为当前 agent 安装 kitsune-mode 和 kitsune-setup。
```

会话不在仓库时，给出 `INSTALL.md` 的实际路径。[安装流程](../INSTALL.md)会识别当前宿主，寻找受支持的位置，再安装两个完整目录及支持文件。仅存在于本仓库不代表宿主已发现它们。不要求先安装第三个 skill，也不假设所有工具扫描同一路径。

用户未指定位置时，使用实际宿主的个人技能目录。用户指定集中安装目录时，核对发现机制并在支持时建立链接；不把维护者使用的目录作为所有用户默认。默认只安装当前宿主，需要多个工具时明确列出。

安装只写获准的技能目录和发现链接，不生成个人工作流、不启动访谈、不写 `CLAUDE.md`、`AGENTS.md` 或权限设置。更新已有副本前先比较内容，保留本地绑定和用户改动；旧版全局入口需要单独审阅迁移，不能直接叠加。

`kitsune-setup` 只在用户要求配置时使用。它包含 Claude 风格的手动调用标记和 Codex 的隐式调用限制。其他工具可能不识别这些字段，正文仍明确限制用途。不要声称这些字段提供跨工具权限控制。

## 各阶段写什么

| 阶段 | 可能写入的内容 | 不会顺带做的事 |
|---|---|---|
| 按 `INSTALL.md` 安装 | 两个技能的完整副本、当前宿主需要的发现链接 | 不生成偏好，不改个人启动文件 |
| 主动调用 `kitsune-setup` | 经确认的个人目录、获准的可选本地绑定 | 不替日常入口进行启动接入 |
| 首次使用 `kitsune-mode` 接入 | 获准宿主的个人启动文件、可选本地接入记录 | 不自动给所有工具改配置，不重写无关内容 |

个人启动文件可能是 `~/.claude/CLAUDE.md`、`~/.codex/AGENTS.md`，也可能因宿主配置而不同。先核对实际加载机制和授权再写入；没有可用机制时保留 skill 激活方式。具体读取来源见[接入说明](integration.md#宿主还会读取什么)。

## 配置个人目录

显式使用配置入口，简短说明希望覆盖的工作范围。可以提供零个、一个或多个项目、交付物、片段或任务描述，每个来源分别确定用途、允许读取的范围和排除项。过程中可以追加来源，agent 应只复核受影响的结论，不重启整个访谈，也不把一个来源的授权扩展到其他来源。

agent 先有限预读，再用通用框架检查目标与产物、执行方法、质量标准、验证证据、取舍与例外、协作方式。框架用于发现缺口，不预置用户偏好。开发、调研等宽泛标签只是导航，重要场景要细化到有输入、产物和约束的具体任务。

关键任务不仅讨论何时做什么，还要有可审阅的方法草稿和质量判断依据。agent 可提出步骤和可信对照，由用户纠正关键判断，不要求用户设计每个实现细节。没有明确方法或质量要求时，保持开放或暂缓状态，不把问过决策问题当成完全覆盖。简单事项、已委托判断和有理由的不适用项不需要硬凑问题。

宿主支持选择界面时，有限选项使用该界面，同时允许其他回答和暂缓。结束前明确补查遗漏任务、可追加资料，以及是否还有知道要做什么却不知道怎样做好的任务。详细步骤见[访谈说明](../skills/kitsune-setup/references/interview.md)和[覆盖框架](../skills/kitsune-setup/references/framework.md)。

审阅生成的行为摘要、选定技能和文件范围。个人目录按固定顺序确定：本次明确指定的路径优先，其次沿用已有绑定，两者都没有时使用 `~/.kitsune/workflow/`。`~` 表示实际宿主用户的主目录，不是当前项目目录。

不需要每次重新选择保存位置。创建前展示解析后的实际路径，已有文件先检查再修改，不静默覆盖。绑定无效或已选目录不可用时报告问题，不悄悄退回默认位置生成另一份配置。个人内容使用你能准确审阅的语言，回复语言单独设置。

已有个人目录时说明这是更新，避免生成平行副本。后续变更统一读取其中的 `maintenance.md`。

## 绑定日常入口

配置入口可在获准后，给已安装的日常 skill 写入 `local/workflow.json`，记录版本 `1` 和绝对 `workflowRoot`。这个文件是本机数据，不应提交到可复用源码。

宿主不允许写本地绑定时，默认目录仍可按约定定位。如果使用自定义目录且没有可保存的绑定，需要在激活时提供该路径。默认目录尚不存在时，日常入口会提示配置，不会在普通任务中自行创建。

## 日常使用

完成绑定后，直接提需求。模型可以选择日常入口，也可手动激活。它读取个人核心，按需补读方法和选定技能，不会重新运行配置访谈。

首次激活时，日常入口会检查启动加载能力，说明具体修改并请求尚缺的授权。实际接入方式见[接入说明](integration.md)。已接入后不应每轮重写设置；已经拒绝也不应反复提示。

## 更新和停用

说清楚是修改当前答案，还是今后持续采用某项要求。清楚的持久修改请求不需要再次批准同一范围，推断与冲突需要确认。

要求停用启动接入时，只移除获准的受管理内容并记录停用。个人文件和已安装技能仍然保留。完全卸载或删除个人资料是另外的操作，不作为停用副作用。

## 查看样例与验证

[样例个人目录](../examples/personal-workflow/README.md)属于虚构用户，只演示文件结构、双语分工及维护方式。不要把样例偏好当成当前用户的选择。

[检查说明](testing.md)列出了本地检查与真实会话检查的区别。是否触发、是否加载、是否正确执行，应分别报告。
